# 可视化实验页页面规范

> 本文档定义“可视化实验页”的页面级规范。
> `速度与位移轨迹` 仅作为参考实现，不作为规范本体。

相关文档：

- `docs/standards/visual-lab-components.md`
- `docs/standards/visual-lab-reference-motion-track.md`

## 1. 文档定位

本文档回答三个问题：

1. 可视化实验页的固定页面骨架是什么。
2. 哪些规则必须遵守，哪些可以按知识点调整。
3. 这些设计为什么更适合教学场景。

本文档不负责：

- 复述某一个具体页面的所有实现细节。
- 定义单个知识点的业务逻辑。
- 代替组件文档说明参数控件的每个属性。

## 2. 适用范围

适用于本项目中所有以“实验、演示、观察、推导”为核心的教学页面，包括但不限于：

- 力学
- 电学
- 光学
- 热学
- 后续数学、化学或其他需要主舞台演示的内容

## 3. 设计目标

可视化实验页首先是教学页面，其次才是普通业务页面。页面结构必须优先服务以下目标：

1. **主舞台优先**：学生的注意力应首先落在可视化过程本身。
2. **操作与观察分离**：参数和按钮放在控制区，主舞台尽量保持纯净。
3. **同一知识点表达一致**：2D / 3D 只切换表达方式，不切换业务定义。
4. **区域稳定**：播放、暂停、调整参数时，用户不应频繁丢失视线焦点。
5. **复用优先**：优先复用统一组件和统一布局，不为单页重复造控件。

## 4. 页面固定骨架

可视化实验页默认采用“两栏实验台”结构：

```text
+------------------------------------------------------+
| 顶部导航 / 页面外壳                                   |
+--------------------------+---------------------------+
| 左侧参数控制面板         | 右侧可视化主舞台          |
| - 实验控制               | - 主可视化区域            |
| - 模式切换               | - 视图切换 / 全屏         |
| - 核心参数               | - 必要 HUD / 总结条       |
| - 显示项                 |                           |
+--------------------------+---------------------------+
```

### 4.1 左侧控制面板

职责：

- 承载参数、模式、播放控制、显示项。
- 承载“改动实验条件”的交互。
- 承载需要高频操作的按钮和滑杆。

不承担：

- 大面积讲解文案。
- 主可视化信息展示。
- 与主舞台并列的第二演示区。

### 4.2 右侧主舞台

职责：

- 作为唯一的观看中心。
- 直接呈现 2D 或 3D 演示。
- 承载必要的舞台内状态提示。

不承担：

- 与左侧重复的参数设置。
- 冗长的说明区块。
- 多层嵌套卡片造成的二次分散注意力。

### 4.3 浮层工具

默认允许存在的浮层工具只有两类：

- `2D / 3D` 视图切换
- 全屏切换

原则：

- 固定位置。
- 占用面积尽量小。
- 不与主视觉主体重叠。

## 5. 信息层级

可视化实验页的信息展示必须分级，避免“所有信息同等重要”。

### 一级信息：主可视化

优先级最高，包含：

- 轨道、物体、力、光路、电路、液面、图形等主对象
- 动画过程本身
- 关键状态变化

要求：

- 尺寸最大
- 对比最强
- 不被大块说明遮挡

### 二级信息：必要状态

包含：

- 当前模式
- 当前实验状态
- 当前时间 / 关键数值
- 当前视图说明

要求：

- 以 HUD、summary bar、角标形式存在
- 信息量少
- 可快速扫读

### 三级信息：辅助教学信息

包含：

- 分组对照
- 课堂结论
- 引导性提示
- 次级图表

要求：

- 不抢一级信息
- 能看懂，但不强迫用户持续盯住

## 6. 教学优先级规则

当视觉美观、信息完整、交互便利三者冲突时，按以下顺序取舍：

1. **先保证主舞台可观察**
2. **再保证参数调整顺手**
3. **最后再补充辅助解释**

换句话说：

- 不能为了塞更多解释牺牲观看空间。
- 不能为了“科技感”做出会干扰观察的背景。
- 不能为了视觉统一，把关键控制埋到不顺手的位置。

## 7. 硬规范

以下规则默认必须遵守。

| 规则 | 说明 |
| --- | --- |
| 左控右演示 | 左侧是参数控制，右侧是主舞台 |
| 控制面板可收起 | 收起后保留最小展开入口 |
| 主舞台尽量铺满剩余宽度 | 不额外再套多层无意义外容器 |
| 页面尽量不出现整页滚动 | 优先控制区滚动或局部区域滚动 |
| 参数只放左侧 | 不把同类参数再次散落到主舞台四周 |
| 视图切换位置固定 | 默认放主舞台左上角 |
| 全屏入口固定 | 默认悬浮在主舞台右上角 |
| 2D / 3D 共用一套业务参数 | 只切视图，不切业务含义 |
| 优先复用统一控件 | 按钮、滑杆、chip、状态条统一来源 |
| 主题色单点强调 | 单页只保留一个主强调色系统 |

## 8. 软规范

以下规则默认推荐遵守，但可按知识点调整。

| 项目 | 默认建议 | 可调整边界 |
| --- | --- | --- |
| 是否提供 3D | 有空间直觉价值时提供 | 纯解析型知识点可只有 2D |
| 是否提供图表 | 有趋势或对照需求时提供 | 纯结构观察页面可不带图表 |
| 控制面板 section 数量 | 3 到 5 组 | 复杂实验可适度增加 |
| 主舞台 HUD 位置 | 左上 / 底部优先 | 不遮挡主体即可 |
| 对照数据展示方式 | summary bar 或轻量面板 | 不强制要求独立侧栏 |
| 默认主题色 | 随实验主题定义 | 但不能多主题并列竞争 |

## 9. 常见反模式

以下做法默认视为反模式：

1. 把大量说明文字堆在主舞台内。
2. 把主舞台再包一层“为了像卡片而存在”的大卡片。
3. 左右两侧都出现参数调节，职责重复。
4. 一页同时堆很多同权重信息区，导致视觉中心缺失。
5. 每个实验自己做一套按钮、切换器、滑杆。
6. 把参考页的所有细节原样复制到不适合的知识点。
7. 为了“科技感”加入会干扰图表或轨迹观察的重背景。

## 10. 规范落地顺序

新实验页落地时，默认按以下顺序设计：

1. 先确定页面骨架：左控右演示。
2. 再确定主舞台里真正要看的核心对象。
3. 再定义左侧参数分组。
4. 再决定是否需要 2D / 3D。
5. 最后补充 HUD、图表、结论条等辅助层。

不要反过来先设计一堆卡片和提示，再勉强给主舞台留空间。

## 11. 与参考实现的关系

当前参考实现页面为：

- `web-app/app/components/motion-track-lab.tsx`

它用于说明“规范如何落地”，但不应被误解为：

- 每个实验都必须有同样的图表
- 每个实验都必须有完全一致的 section 文案
- 每个实验都必须复制它的每一个浮层布局

它的价值在于：

- 给出了优秀的主舞台优先级
- 给出了可复用的控制区组织方式
- 给出了 2D / 3D 并存时的稳定页面骨架
