# 速度与位移轨迹参考实现说明

> 本文档说明为什么 `速度与位移轨迹` 页面适合作为参考实现。
> 它是“样板页说明”，不是页面规范本体。

相关规范：

- `docs/standards/visual-lab-page-spec.md`
- `docs/standards/visual-lab-components.md`

参考实现文件：

- `web-app/app/components/motion-track-lab.tsx`
- `web-app/app/components/motion-track-three-stage.tsx`
- `web-app/app/app.css`

## 1. 为什么它适合作为参考实现

这页的价值不在于“它有图表”或“它有 3D”，而在于它同时满足了几件重要的事：

1. 主舞台始终是页面焦点
2. 左侧参数区职责清晰
3. 2D / 3D 共用一套业务参数
4. 播放、暂停、重置的实验流程明确
5. 主题色、浮层、图表、状态提示已经形成稳定设计语言

## 2. 它体现出的页面规范

### 2.1 页面骨架正确

页面采用稳定的两栏结构：

- 左侧控制区
- 右侧主舞台

对应实现：

- `web-app/app/components/motion-track-lab.tsx`
- `web-app/app/app.css`

### 2.2 控制区按教学流程组织

左侧不是简单参数列表，而是按教学顺序组织：

1. 实验控制
2. 运动模式
3. 核心参数
4. 显示项

这使页面天然支持“先播放观察，再切模式，再改参数，再切辅助视图”。

### 2.3 主舞台信息分层合理

右侧主舞台同时包含：

- 轨道主体
- 图表
- 必要浮层
- 全屏和视图切换

但主对象仍然是轨道和小车，没有被说明块压住。

### 2.4 2D / 3D 切换边界清楚

2D 和 3D 只是表达差异：

- 2D 更强调解析和图表
- 3D 更强调空间直觉和跟随视角

但参数、模式、时间轴、播放状态保持一致。

## 3. 这页值得继承的部分

后续其他实验页，优先继承以下内容：

### 必须优先继承

- 左控右演示骨架
- 控制面板收起逻辑
- 主舞台优先的布局原则
- 2D / 3D 视图切换位置
- 全屏按钮悬浮位置
- 统一控件体系

### 强烈建议继承

- section 分组方式
- 主按钮 / 次按钮层级
- 轻量 HUD 的表达方式
- 单主题强调色
- 深色舞台 + 浅色控制区的对比关系

## 4. 这页不应该被硬复制的部分

这页也有很多内容是“业务特有”，不应该被当成强制规范。

### 4.1 图表不是所有页面都必须有

这页适合带图表，因为它天然有：

- 位移随时间变化
- 速度随时间变化
- 匀速 / 加速 / 减速对照

但例如纯结构观察、电路搭建、成像位置判断类页面，不一定要复制双图表布局。

### 4.2 “运动模式”不是所有页面都通用

匀速 / 加速 / 减速是本页专属业务抽象，不能套给其他实验。

### 4.3 秒级采样点和轨道尺不是所有页面都要保留

它们适合讲：

- 速度变化
- 时间离散采样
- 位置对照

不适合的知识点不应机械保留。

### 4.4 底部 summary bar 的具体指标不是通用规范

summary bar 这种承载方式值得复用，但其中显示哪些指标应由知识点决定。

## 5. 这页最值得学习的不是“长什么样”，而是“怎么取舍”

它做得好的关键不只是视觉，而是取舍清楚：

- 参数留在左侧，不塞进主舞台
- 主舞台背景有科技感，但不会抢主对象
- 信息足够多，但不会全部同权重
- 3D 是补充表达，不是另一套业务页面

这类取舍，才是后续页面应该复用的经验。

## 6. 使用方式建议

后续开发新的实验页时，建议按以下方式使用本参考页：

1. 先读 `visual-lab-page-spec.md`，确认页面骨架
2. 再读 `visual-lab-components.md`，确认组件边界
3. 最后参考本页，学习如何把规范落成可用页面

不要反过来直接复制 `motion-track-lab.tsx` 的页面结构再删改。

## 7. 当前结论

`速度与位移轨迹` 应继续作为：

- 当前项目的首选参考实现页
- 新实验页的布局和信息层级基准

但它不应继续被当成：

- 规范文档本身
- 所有实验页的一比一模板
