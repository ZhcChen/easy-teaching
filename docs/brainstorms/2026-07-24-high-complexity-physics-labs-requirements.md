# 高复杂度物理实验后置门槛

## Problem Frame

当前 `web-app` 已经建立起一条相对稳定的课堂页生产线：

- 直观力学页
- 几何光学页
- 变量 + 图表页

但归档里仍然有几类主题不能直接沿用现有脚手架：

- `凸透镜成像规律`
- `光的折射规律`
- `浮力与阿基米德原理`
- `晶体与非晶体熔化凝固实验`
- `滑动变阻器动态调压实验`

这些主题并不是“不值得做”，而是它们对共享能力的要求明显高于前四个交付波次。如果不先把进入门槛写清楚，后续执行很容易重新退回“哪个看起来有意思就先做哪个”的随机开发模式。

## Archive Findings

| 主题 | 当前主要复杂度 | 为什么不能直接复用现有页 |
|---|---|---|
| 凸透镜成像规律 | 多工况切换、实像/虚像切换、光路作图 | 不是单一几何关系，而是按 `u` 与 `f` 的区间跳变成像性质 |
| 光的折射规律 | 双介质、角度关系、不同介质折射率 | 需要稳定的“介质边界 + 法线 + 折射方向”表达层 |
| 浮力与阿基米德原理 | 浸入过程、排液、力与体积联动 | 需要同时处理液面、排液、测力计和受力变化 |
| 晶体与非晶体熔化凝固 | 温度-时间曲线、平台段、状态变化 | 需要更成熟的图表脚手架和状态分层表达 |
| 滑动变阻器动态调压 | 动态接线、安全初值、分压与分流关系 | 需要比欧姆定律更完整的器材接线与状态保护逻辑 |

## Requirements

### backlog 管理

- R1. 上述 5 个主题都要进入 catalog，但统一标记为 `backlog`，不冒充近期可开始页。
- R2. 每个主题都要有清晰的后置理由，避免后续再次用模糊描述掩盖复杂度来源。

### 进入门槛

- R3. `凸透镜成像规律` 进入实现前，必须先有稳定的多工况光路舞台，能处理实像、虚像和临界位置切换。
- R4. `光的折射规律` 进入实现前，必须先有稳定的双介质边界、法线、入射角/折射角与介质切换表达。
- R5. `浮力与阿基米德原理` 进入实现前，必须先有液体容器、浸入体积、排液与测力读数联动的共享能力。
- R6. `晶体与非晶体熔化凝固` 进入实现前，必须先有足够成熟的温度-时间图表层，能表达平台段与状态切换。
- R7. `滑动变阻器动态调压` 进入实现前，必须先有更完整的电学器材层，包括接线正确性、安全初值和动态分压可视化。

## Key Decisions

- **全部进入 catalog，但全部保持 backlog。**
  - 这样目录会真实反映“后面确实要做什么”；
  - 也能避免用户误以为这些主题已经进入近期排期。

- **复杂度要写成共享能力缺口，而不是抽象地说“以后再做”。**
  - 后续只要共享能力补齐，就能顺势把对应主题从 backlog 下调为 planned；
  - backlog 不再是无限期搁置，而是有明确触发条件的队列。

## Success Criteria

- 初中物理 catalog 中，高复杂度主题都能被清楚看见，但不会冒充“可开始”。
- 每个高复杂度主题都对应一个明确的前置条件集合。
- 后续排期讨论时，可以直接围绕“共享能力是否成熟”判断是否升档，而不是重新做一轮主题辩论。

## Scope Boundaries

- 本轮只完成队列与门槛定义，不实现这些实验页。
- 本轮不重构现有 `ohms-law-lab`、`light-reflection-lab` 或其他实验页。
- 本轮不引入新的可视化组件，只做文档与 catalog 收口。

## Next Steps

- 当图表层继续成熟时，优先重新评估 `melting-freezing-lab` 是否能从 backlog 下调。
- 当电学器材层有进一步抽象后，优先重新评估 `variable-resistor-lab`。
- 当光学页需要更复杂的光路作图时，再一起评估 `lens-imaging-lab` 与 `light-refraction-lab`。
