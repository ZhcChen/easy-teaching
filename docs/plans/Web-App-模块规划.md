# Web App 模块规划

> 状态：当前主路线。自 2026-07-16 起，因微信小程序方向受限，前端主交付切换为 Web App。

## 当前结论

- 仓库根目录新增 `web-app/` 模块
- 当前前端主路线切换为 **Web App**
- 目标同时覆盖：
  - `PC`
  - `H5`
- 当前先落模块骨架与规划，不手工生成具体框架模板
- 后续正式初始化时，优先使用所选框架的最新官方脚手架

## 为什么改为 Web App

- 不再受微信小程序单平台限制
- 更适合同时覆盖桌面端与移动浏览器
- UI、交互、可视化能力更容易统一设计
- 后续接入账号、同步、后台管理与内容分发也更自然

## 模块定位

根目录模块建议调整为：

- `web-app/`：当前主 Web 前端模块，面向 PC + H5
- `ui-design-preview/`：UI 设计与交互预览模块
- `wechat-miniprogram/`：历史路线参考，暂不作为当前主线
- `docs/`：规划、方案、归档
- `shared-assets/`：共享品牌与公共资源

## Web App 目标

### 1. 平台目标

- PC 浏览器
- 移动浏览器 H5

### 2. 设计目标

- 一套内容结构同时服务 PC 与 H5
- 桌面端强调信息密度与多栏布局
- H5 强调单列滚动、触控与轻量交互

### 3. 业务目标

- 先承接当前可视化教学内容
- 后续支持物理、数学、化学与记忆教学
- 保留本地优先数据设计，后续再接云端同步

## 信息架构沿用原则

虽然交付端从小程序切换为 Web App，但核心信息架构不变，继续采用：

- `首页 / 内容 / 学习 / 我的`

内容主路径仍建议保持：

- `学段 -> 学科 -> 章节/专题 -> 内容`

对应说明文档：

- `docs/plans/小程序信息架构与本地优先同步方案.md`

该文档中的以下结论仍然有效：

- 学段和学科不放在底部主导航里
- 内容和学习分离
- 本地优先存储
- 后续通过同步中心接入云端

## 响应式方向

### PC

- 适合双栏或三栏布局
- 左侧可以承载导航、筛选、目录树
- 主区域承载内容、实验、图解和学习卡片

### H5

- 采用单列滚动布局
- 顶部或底部保留主导航
- 学段、学科、筛选项使用抽屉、标签或横向滚动

## 当前建议目录

当前先落一个中性骨架：

```text
web-app/
├─README.md
├─public/
└─src/
  ├─assets/
  ├─components/
  ├─layouts/
  ├─pages/
  ├─store/
  ├─styles/
  └─utils/
```

说明：

- 当前只是预留模块边界与结构
- 不在这一轮手工伪造具体框架模板
- 等你确定具体框架后，再用最新官方方式初始化

## 技术策略

当前先采用两段式推进：

### 第一阶段

- `ui-design-preview/` 继续承接视觉方向确认
- `web-app/` 只先建立模块骨架、约定与说明

### 第二阶段

- 选定实际 Web 技术栈
- 使用最新官方脚手架初始化 `web-app/`
- 按已确认的 UI 和信息架构落正式页面

## 数据策略

继续沿用本地优先原则：

- 当前用户数据先保存在本地
- 后续有一定用户量后，再进入云端同步阶段

建议保留的数据类型：

- 学段偏好
- 学科偏好
- 最近学习记录
- 收藏
- 学习历史
- 学习进度
- 实验参数记录
- 笔记 / 记忆数据
- 同步状态

## 与现有模块关系

### `ui-design-preview/`

- 当前继续作为视觉与交互预演模块
- 后续优先服务 `web-app/`，不再仅面向小程序

### `wechat-miniprogram/`

- 当前保留为历史参考
- 暂不作为主线继续推进
- 若后续政策或业务条件变化，再决定是否恢复

4. 确认实际 Web 技术栈后，再初始化正式工程
