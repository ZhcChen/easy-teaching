# Web App 模块规划

> 状态：当前主路线。自 2026-07-16 起，因微信小程序方向受限，前端主交付切换为 Web App。

## 当前结论

- 仓库根目录新增 `web-app/` 模块
- 当前前端主路线切换为 **Web App**
- 目标同时覆盖：
  - `PC`
  - `H5`
- 技术栈采用：
  - `React`
  - `PixiJS` 负责 2D 可视化
  - `Three.js` 负责 3D 可视化
- 本地开发端口预留为：`57001`
- 第三方库不使用 CDN 引入，统一走项目本地依赖
- `web-app/` 已使用 React Router 官方最新脚手架完成初始化
- 当前已落一级路由基座：首页、内容、学习、我的

## 为什么改为 Web App

- 不再受微信小程序单平台限制
- 更适合同时覆盖桌面端与移动浏览器
- UI、交互、可视化能力更容易统一设计
- 后续接入账号、同步、后台管理与内容分发也更自然

## 模块定位

根目录模块建议调整为：

- `web-app/`：当前主 Web 前端模块，面向 PC + H5
- `app/`：Electron 桌面宿主模块，直接复用 `web-app/` 前端产物
- `ui-design-preview/`：UI 设计与交互预览模块
- `wechat-miniprogram/`：历史路线参考，暂不作为当前主线
- `docs/`：规划、方案、归档
- `shared-assets/`：共享品牌与公共资源

## Web App 目标

### 1. 平台目标

- PC 浏览器
- 移动浏览器 H5

### 2. 设计目标

- 一套内容结构同时服务 PC 与 H5
- 桌面端强调信息密度与多栏布局
- H5 强调单列滚动、触控与轻量交互

### 3. 业务目标

- 先承接当前可视化教学内容
- 后续支持物理、数学、化学与记忆教学
- 保留本地优先数据设计，后续再接云端同步

## 技术栈结论

### React

- 负责应用壳子、路由、状态管理、响应式布局
- 同时承接 PC 与 H5 页面组织

### PixiJS

- 用于 2D 可视化场景
- 适合轨迹、坐标系、受力分析、图解、动画和高频 2D 交互

### Three.js

- 用于 3D 可视化场景
- 适合立体几何、分子结构、空间演示和未来复杂 3D 内容

### 双引擎原则

- `2D` 内容优先走 `PixiJS`
- `3D` 内容优先走 `Three.js`
- 两者都挂在 `React` 外层应用之下
- 不强行用单一引擎覆盖所有场景

## 第三方库引入原则

- 不使用 CDN 脚本标签引入
- 统一通过项目本地依赖管理
- 正式工程内通过包管理器安装后，由构建工具参与打包
- 不建议把第三方库的整份 dist 文件直接手工拷贝进业务源码目录

说明：

- `pixi.js` 官方 npm 包当前版本 `8.19.0`，npm registry 显示 `dist.unpackedSize = 72,415,382 bytes`
- 其中核心浏览器构建文件 `dist/pixi.min.js` 约 `797.8 kB`
- `three` 官方 npm 包当前版本 `0.185.1`，npm registry 显示 `dist.unpackedSize = 23,172,772 bytes`
- 其中核心浏览器构建文件 `build/three.module.min.js` 约 `365.6 kB`

结论：

- 如果是“整包 dist 全拷本地”，`PixiJS` 会显得偏大，`Three.js` 中等
- 如果是“本地依赖 + 工程打包”，体积是可控的，实际应以最终构建产物为准

## 信息架构沿用原则

虽然交付端从小程序切换为 Web App，但核心信息架构不变，继续采用：

- `首页 / 内容 / 学习 / 我的`

内容主路径仍建议保持：

- `学段 -> 学科 -> 章节/专题 -> 内容`

对应说明文档：

- `docs/plans/小程序信息架构与本地优先同步方案.md`

该文档中的以下结论仍然有效：

- 学段和学科不放在底部主导航里
- 内容和学习分离
- 本地优先存储
- 后续通过同步中心接入云端

## 响应式方向

### PC

- 适合双栏或三栏布局
- 左侧可以承载导航、筛选、目录树
- 主区域承载内容、实验、图解和学习卡片

### H5

- 采用单列滚动布局
- 顶部或底部保留主导航
- 学段、学科、筛选项使用抽屉、标签或横向滚动

## 与现有模块关系

### `ui-design-preview/`

- 当前继续作为视觉与交互预演模块
- 后续优先服务 `web-app/`，不再仅面向小程序

### `app/`

- 作为桌面端交付层存在
- 不维护独立页面业务源码
- 开发态直接加载 `web-app/` 开发服务
- 构建态先同步 `web-app/build/client` 到 `app/dist/`
- 打包后的 Electron 通过本地静态服务加载 `app/dist/`
- 这样可以让 Web 与桌面端默认保持同一套前端功能

### `wechat-miniprogram/`

- 当前保留为历史参考
- 暂不作为主线继续推进
- 若后续政策或业务条件变化，再决定是否恢复
