# 资产预览模块规划

> 状态：2026-07-20 新增。当前核心目标不是做复杂后台，而是做“资产预览工作台”。

## 当前结论

- 仓库根目录新增模块：
  - `asset-studio/`
- 技术栈采用：
  - `Vite 8`
  - `React`
- 本地开发端口：
  - `57002`
- 当前模块定位不是资源上传后台，也不是 CMS，而是：
  - 资产预览
  - 方案对比
  - 配色浏览
  - 资源归类查看

## 为什么要单独做这个模块

当前教学产品后续会持续引入：

- 小车、受力块、坐标轴、粒子、几何体、分子结构等可视化资产

如果这些资产只散落在业务模块里，会出现：

- 不方便统一看设计效果
- 颜色与风格难以收敛
- 资源归属不清楚
- 后续替换与复用成本高

所以需要一个独立模块，专门让资产“被看见、被比较、被确认”。

## 模块定位

`asset-studio/` 当前只做一件核心事情：

- 让我能直接预览你设计出来的资产，看它是否合适

因此第一阶段优先满足：

1. 资产大图预览
2. 深浅背景预览
3. 多配色方案对比
4. 资源分类查看
5. 资源说明与引用路径查看

暂时不优先做：

- 本地文件上传
- 文件移动/删除
- 在线编辑 SVG 路径
- 复杂权限系统

## 与公共资源目录的关系

当前仓库已经有公共资源目录：

- `shared-assets/`

因此不再新增第二个公共资产根目录。

采用以下分工：

- `shared-assets/`：存放公共资产母版、配置与说明
- `asset-studio/`：专门做预览、浏览、方案比较
- `web-app/`：实际消费这些资产

## 第一批目标资产

首批先围绕物理运动学内容落地：

- `subjects/physics/mechanics/motion-track/cart/`

第一批资产目标：

- 一个标准侧视小车形态
- 多个颜色预设
- 能适配深色可视化场景
- 看起来更像“小车”，而不是简单几何块

## 预览工作台设计重点

页面重点不放在“管理表单”，而放在“看效果”：

### 左侧

- 资源分类
- 当前资产列表
- 预览目标说明

### 中间

- 大尺寸主预览区
- 不同背景场景下的资产效果
- 多配色方案卡片对比

### 右侧

- 资源路径
- 标签
- 适用模块
- 颜色 token
- 设计说明

## 数据组织建议

第一阶段优先使用轻量配置驱动：

- `JSON` 记录资产元数据与配色方案

例如：

- 资产 ID
- 标题
- 所属分类路径
- 标签
- 目标模块
- 部件说明
- 配色预设

这样后续即使换实现方式，也能保留同一份资产定义。

## 第一阶段执行顺序

1. 新增 `asset-studio/` 模块
2. 配置 `57002` 端口
3. 补首批小车资产定义与说明
4. 做一版以预览为中心的工作台
5. 让用户先看资产效果，再决定是否接入业务可视化

## 当前阶段结论

- `asset-studio/` 走“预览优先”
- `shared-assets/` 继续作为唯一公共资源根目录
- 首批重点资产就是物理运动轨迹里的小车
- 先让资产本身好看、可比较、可确认，再进入业务接线
