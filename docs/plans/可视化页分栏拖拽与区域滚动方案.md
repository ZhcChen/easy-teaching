# 可视化页分栏拖拽与区域滚动方案

## 背景

当前 `web-app` 的基础受力分析页已经具备左侧控制面板与右侧可视化画布，但仍有两个问题：

- 页面整体会出现纵向滚动，影响演示沉浸感
- 左右区域之间是普通间距，不支持拖拽调节宽度

这会导致参数项较多时，左侧面板阅读与操作空间不够灵活。

## 本次目标

围绕 `web-app/app/components/basic-force-lab.tsx` 与 `web-app/app/app.css`，完成以下改造：

1. 桌面端可视化页优先改为“页面不滚动，区域内部滚动”
2. 左右区域合并为一个整体工作区，中间使用较宽分割条分隔
3. 分割条支持鼠标左右拖拽，实时调整左侧面板宽度
4. 拖拽后的宽度记录到浏览器本地存储
5. 左右区域内容在宽度变化后保持自适应排版

## 设计原则

### 1. 页面级固定，区域级滚动

- 可视化页在桌面端固定在视口高度内
- 顶部导航保留
- 主内容区不再依赖整页滚动
- 左侧控制面板与右侧画布区域分别承担内部滚动

这样能保证：

- 可视化区域始终尽量大
- 参数再多也不把整页拉长
- 全屏 / 非全屏的操作心智更统一

### 2. 左右区域合并为一个工作壳

- 保留一个统一的外层容器
- 左右区域不再只是“两个并列卡片”
- 中间通过较宽拖拽分隔条做视觉与交互分界

这样更接近桌面工作台的使用方式，也更适合后续更复杂的实验页。

### 3. 拖拽宽度可记忆

- 左侧面板宽度使用 `localStorage` 保存
- 下次再次打开页面时恢复上次宽度
- 需要做最小/最大宽度钳制，避免拖拽后布局失控

## 实现方案

## 一、布局层

在可视化路由下增加“视口高度锁定”能力：

- `body` / `main` 在可视化页进入 `overflow: hidden`
- `page-shell` 与 `visual-page` 继承整屏高度
- `force-lab-shell` 作为统一工作壳，占满可用高度

## 二、分栏层

`force-lab-layout` 从原来的两列网格改为三列：

- 左侧控制面板
- 中间分割条
- 右侧画布区

其中：

- 展开态：`面板宽度 + 分割条宽度 + 自适应主区`
- 收起态：保留收起按钮列，隐藏分割条宽度

## 三、拖拽层

在 React 组件内新增：

- 面板宽度状态
- 是否正在拖拽状态
- 布局容器引用

交互流程：

1. 鼠标按下分割条
2. 监听 `pointermove`
3. 根据指针位置计算左侧面板新宽度
4. 按最小/最大边界钳制
5. 松开后结束拖拽并持久化

## 四、排版自适应

为了适配左侧面板宽度变化，需要同步优化：

- 参数标签行允许更自然换行
- 状态卡片区改为更弹性的 `auto-fit` 布局
- 步骤说明、按钮组、标签组在窄宽度下面能自动折行
- 右侧画布容器保持填满剩余宽度，并优先撑满高度

## 五、响应式边界

本次重点先服务桌面端：

- 桌面端启用整屏工作区 + 拖拽分栏
- `900px` 以下继续退化为纵向堆叠
- 小屏场景不强行保留拖拽分栏

## 预期结果

改造完成后，基础受力分析页应具备以下体验：

- 页面本身基本不滚动
- 左侧控制项多时，在左侧区域内部滚动
- 右侧画布保持更大的稳定观看空间
- 左右区域之间可拖拽调节宽度
- 下次进入时恢复上次拖拽后的面板宽度
