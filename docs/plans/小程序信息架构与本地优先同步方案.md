# 小程序信息架构与本地优先同步方案

## 当前结论

- 底部导航采用 4 个 tab：`首页 / 内容 / 学习 / 我的`
- 学段与学科不放在 tabBar 中，而是放在页面内部做主入口和筛选
- 内容主结构采用：`学段 -> 学科 -> 章节/专题 -> 内容`
- 当前阶段先全量本地存储
- 后续接入云开发时，通过“手动同步”把本地数据同步到云端

## tabBar 设计

### 1. 首页

职责：

- 学段主入口：`初中 / 高中`
- 学科快捷入口
- 最近学习
- 推荐内容
- 热门专题

说明：

- 学段切换应足够明显，避免初高中内容混杂
- 如果后续只有单学科阶段，也仍然保留学段入口，便于平滑扩展

### 2. 内容

职责：

- 承担全量内容库浏览
- 顶部提供内容筛选

建议筛选维度：

- 学段
- 学科
- 章节
- 类型

建议内容类型：

- 实验
- 动画
- 图解
- 记忆
- 专题

说明：

- 理科和文科内容统一从这里进入
- 物理、数学、化学和记忆教学都使用同一内容框架

### 3. 学习

职责：

- 最近学习
- 收藏
- 学习历史
- 学习进度
- 本地笔记
- 实验参数记录

说明：

- 这是“本地优先”设计下最重要的沉淀页
- 与内容浏览分开，突出个人学习数据

### 4. 我的

职责：

- 数据同步中心
- 本地数据管理
- 设置
- 反馈
- 账号能力预留

说明：

- 后续云开发接入后，同步相关入口统一放这里
- 不把同步入口散落到多个页面

## 入口结构

推荐主路径：

1. 首页先选学段：`初中 / 高中`
2. 进入后展示该学段下的学科入口
3. 再进入章节或专题
4. 再进入具体内容页

内容列表页也支持直接筛选：

- 学段
- 学科
- 类型

这样可以同时满足：

- 新用户按路径探索
- 老用户按筛选快速直达

## 页面结构建议

```text
tabBar
├─首页
│ ├─学段切换
│ ├─学科快捷入口
│ ├─最近学习
│ ├─推荐内容
│ └─热门专题
├─内容
│ ├─筛选栏
│ ├─内容列表
│ ├─章节页
│ └─内容详情/实验详情
├─学习
│ ├─最近学习
│ ├─收藏
│ ├─历史
│ ├─学习进度
│ └─笔记/记录
└─我的
  ├─数据同步中心
  ├─本地数据管理
  ├─设置
  └─反馈
```

## 本地优先原则

当前阶段虽然已开通云开发能力，但业务设计按“本地先跑通”处理：

- 所有学习数据先写本地
- 没有账号也能正常使用
- 云开发暂不作为当前主流程依赖
- 后续有一定用户量后，再引导用户把本地数据同步到云端

这样做的好处：

- 当前开发成本更低
- 不被账号体系和云端模型阻塞
- 功能迭代更快

## 需要本地保存的数据

建议至少保存以下内容：

- 当前学段偏好
- 当前学科偏好
- 最近学习记录
- 收藏
- 学习历史
- 学习进度
- 实验参数记录
- 笔记或记忆数据
- 本地同步状态

## 数据模型预留字段

为了后续能平滑同步到云开发，建议本地记录从一开始就带上统一字段：

- `localId`
- `contentId`
- `updatedAt`
- `syncStatus`
- `deleted`

其中：

- `localId`：本地唯一标识
- `contentId`：关联内容或实验
- `updatedAt`：最近更新时间
- `syncStatus`：同步状态
- `deleted`：逻辑删除标记

`syncStatus` 建议先约定这些值：

- `local-only`
- `pending`
- `synced`
- `failed`

## 同步中心设计

同步入口放在：

- `我的 -> 数据同步中心`

后续同步流程建议：

1. 用户进入同步中心
2. 查看可同步的数据数量
3. 手动触发同步
4. 同步成功后更新状态
5. 若失败，保留失败记录并允许重试

页面上至少显示：

- 本地数据总数
- 待同步数量
- 上次同步时间
- 最近同步结果

## 开发阶段建议

### 第一阶段

- 先落 `首页 / 内容 / 学习 / 我的`
- 学段、学科、内容结构先跑通
- 所有学习数据先保存到本地

### 第二阶段

- 补齐学习记录、收藏、进度、实验参数等本地数据结构
- 在“我的”中加入同步中心占位

### 第三阶段

- 接入云开发数据库
- 增加手动同步能力
- 增加失败重试与状态展示

## 当前建议落地顺序

1. 先实现 4 tab 信息架构
2. 首页先做学段入口和学科入口
3. 内容页做筛选框架
4. 学习页先做本地记录聚合
5. 我的页先预留同步中心入口
